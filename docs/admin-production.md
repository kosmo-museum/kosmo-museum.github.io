# Админ-панель «Музей в кармане»: от демо к боевой версии на Яндекс Облаке

Статус на 24.11.2026: демо работает на GitHub Pages (https://kosmo-museum.github.io/admin/), сервер для него не нужен. Здесь описано, чем демо отличается от боевой версии, что строить и сколько это стоит.

## 1. Как устроено демо (сейчас)

```
Админка (/admin/) ──черновик──▶ localStorage ──postMessage──▶ превью справа (iframe /app/?preview=1)
       │
       └─«Опубликовать»─▶ GitHub API: app/content.json ─▶ GitHub Pages (~1 мин)
                                                          │
                     телефоны посетителей ◀── опрос content.json раз в 15 с
```

- Весь редактируемый контент — один файл `app/content.json` (схема — `docs/content-schema.md`).
- Превью справа обновляется мгновенно, ещё до публикации.
- После «Опубликовать» GitHub Pages пересобирает сайт примерно за минуту. Открытые приложения перечитывают `content.json` раз в 15 секунд и перерисовываются без перезагрузки: появляется событие в афише, приходит уведомление, меняется цена.
- Ограничения демо: вход по общему паролю (это не защита), журнал правок хранится в браузере, ключ GitHub вводит человек, статистика выдуманная, у фото нет загрузки, изменения доходят примерно за минуту.

## 2. Что получает музей в боевой версии

| Раздел | Что делает сотрудник |
|---|---|
| Сводка | Статистика приложения: посетители, экскурсии, популярные экспонаты, переходы к покупке билета. Быстрые кнопки «Создать мероприятие», «Запланировать анонс» |
| Главная | Приветствие, объявление-плашка с переключателем, тексты экскурсии |
| Экспонаты | Название, описание, рассказ Белки, фото и аудио к каждой карточке; поиск; «вернуть исходный текст» |
| Мероприятия | Список и календарь, кнопка «Создать мероприятие», типы (лекция, кино, выставка…), выставки с датой окончания. Прошедшие скрываются сами |
| Экскурсии с гидом | Сеансы по времени, места |
| Анонсы и пуши | Срочное сообщение «прямо сейчас» и анонсы по расписанию; в боевой версии — настоящие пуш-уведомления на телефон |
| Магазин и кафе | Товары, цены, категории, ярлыки |
| Часы и билеты | Часы работы, длинные дни, цена «от», ссылка на Мосбилет |
| Журнал | Кто, что и когда менял; откат к любой опубликованной версии |

Роли: **редактор** правит черновик, **публикатор** выпускает изменения в приложение, **администратор** управляет пользователями.

## 3. Архитектура на Яндекс Облаке

```
Сотрудник музея ──▶ Админка (Object Storage + CDN, вход через Yandex ID / логин + 2FA)
                         │
                         ▼
               API Gateway ─▶ Serverless Containers (API админки)
                         │            │
          Managed PostgreSQL ◀────────┘──▶ Object Storage (фото, аудио)
      (контент, черновики, версии,            │
          пользователи, журнал)               ▼
                         │              Cloud CDN
            «Опубликовать» ─▶ снимок content.json в Object Storage ─▶ CDN ─▶ приложение
                         └─▶ пуши: RuStore Push (Android), APNs (iOS), Web Push (веб-версия)
```

- **Хранение.** Managed Service for PostgreSQL — контент, черновики, версии, пользователи, журнал. YDB в serverless-режиме — альтернатива, если нужно платить только за запросы. Object Storage — фото и аудио; Cloud CDN — раздача.
- **API.** Serverless Containers за API Gateway: CRUD по разделам, публикация, откат, загрузка медиа (подписанные ссылки в Object Storage).
- **Публикация.** Приложение читает не базу, а **опубликованный снимок** JSON из CDN. Так приложение быстрое, а нагрузка на базу не зависит от числа посетителей. Публикация — это новый снимок с номером версии; откат — повторная публикация старой версии.
- **Живые обновления.** Приложение сверяет номер версии раз в 15–30 с (лёгкий запрос к CDN); для мгновенной доставки можно добавить WebSocket через API Gateway.
- **Пуши.** RuStore Push и APNs для нативных версий, Web Push для веб-приложения (на iPhone — только если оно установлено на экран «Домой»). Анонсы по расписанию отправляет Cloud Functions по таймеру.
- **Статистика.** AppMetrica в приложении; сводка в админке забирает агрегаты через её API (или DataLens для подробных отчётов).

### Требования

- **152-ФЗ:** все серверы в регионе ru-central1, данные сотрудников (логины, журнал) хранятся в РФ.
- **Бэкапы:** автоматические бэкапы PostgreSQL (7 дней) и версионирование бакета с медиа.
- **Журнал действий:** в базе (кто, что, когда, старое и новое значение) плюс Audit Trails по облаку.
- **Билеты** продаются на Мосбилете; данные покупателей и карт в нашей системе не хранятся.

### Синхронизация с Яндекс Картами и 2ГИС

Часы работы, временный график и примечания из админки уходят в карточки музея на картах, чтобы не вводить их в трёх местах. Нейросети для этого не нужны: это передача данных через официальные кабинеты.
- **Яндекс Карты** берут данные из Яндекс Бизнеса. Для сетей есть массовое обновление файлом и партнёрская программа поставщиков данных; для одной организации обычно идут через сертифицированную геоплатформу.
- **2ГИС** — через кабинет 2ГИС для бизнеса или ту же геоплатформу (RocketData и аналоги работают с Яндексом, 2ГИС и другими картами по API).
- **Порядок:** подтвердить права музея на карточки в обоих сервисах → выбрать канал (геоплатформа или прямой партнёрский доступ) → при публикации админка отправляет часы в этот канал. Изменения проходят модерацию сервисов, обычно от нескольких часов до суток.
- **Оценка:** +1 неделя к проекту плюс подписка на геоплатформу, если идём через неё.

## 4. Движок: готовая CMS или своя админка

| | Directus / Strapi в своём контейнере | Своя админка (развитие демо) |
|---|---|---|
| Срок до первой версии | 3–4 недели | 6–8 недель |
| Интерфейс | Универсальный: таблицы и формы. Превью приложения встраивать отдельно | Сделан под музей: превью в рамке телефона, календарь, понятные русские подписи |
| Роли, версии, журнал | Есть из коробки | Делаем сами |
| Обучение сотрудников | Нужно: интерфейс общий для всех CMS | Минимальное: всё на языке музея |
| Поддержка | Обновления CMS, совместимость плагинов | Только наш код |

**Рекомендация:** своя админка на базе демо: сотрудники музея уже увидят её на созвоне, а именно понятный интерфейс без IT-терминов — главное требование. Directus оставить запасным вариантом, если сроки окажутся важнее.

## 5. Оценка

**Сроки (своя админка):**

| Этап | Срок |
|---|---|
| Аккаунт и окружение Яндекс Облака, база, хранилище, CDN | 1 неделя |
| API: разделы, черновик и публикация, версии, журнал, загрузка медиа | 2–3 недели |
| Админка: перенос демо на API, вход и роли, фото и аудио экспонатов | 2 недели |
| Пуши и анонсы по расписанию, подключение AppMetrica и сводки | 1–2 недели |
| Тесты с сотрудниками музея, обучение, запуск | 1 неделя |
| **Итого** | **7–9 недель** |

**Стоимость облака в месяц** — это прикидка, её нужно пересчитать в калькуляторе Яндекс Облака под выбранную конфигурацию. Основная статья — минимальный кластер PostgreSQL (2 vCPU, хранилище 20–50 ГБ, бэкапы). Serverless Containers, API Gateway и Cloud Functions при трафике музея укладываются в бесплатный лимит или стоят копейки. Object Storage и CDN зависят от объёма фото и аудио и числа посетителей. Ориентир: **несколько тысяч рублей в месяц**, в основном за базу.

**Кто что делает:**

- **Студия:** архитектура, API, админка, интеграция с приложением, пуши, тесты, обучение, документация.
- **Музей:** юрлицо и платёжный аккаунт в Яндекс Облаке (или доступ к своему); список сотрудников и ролей; контент: тексты, фото, аудио, афиша; согласование с ответственным за персональные данные.
- **Совместно:** кто публикует изменения и кто отвечает за пуши (чтобы не отправлять посетителям лишнего).

## 6. Что нужно, чтобы показать демо

1. Ключ GitHub для кнопки «Опубликовать»: fine-grained токен с правом **Contents: Read and write** только на `kosmo-museum/kosmo-museum.github.io`. Если организация требует одобрять такие токены, одобрить его в настройках организации, или использовать classic-токен с правом `repo`. Ключ вводит человек прямо в админке; в репозиторий он не попадает.
2. Инструкция для созвона — в README.
